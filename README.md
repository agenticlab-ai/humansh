```text
% git status
# runs immediately — humansh recognises a real command and stays out of the way

% show me which process is listening on port 3000
lsof -nP -iTCP:3000 -sTCP:LISTEN
  Generated by Codex. Review it, then press Enter to run.
```

The generated command lands in your editable command line. Nothing runs until you press Enter yourself.

## Why humansh

- **Never auto-executes.** Generated commands are inserted for review. High-risk output is gated behind a second, deliberate key sequence.
- **Runs in your shell, not a wrapper.** Integration happens at the ZLE/Readline layer, so `cd`, `export`, aliases, functions, and job control behave normally. It is not a REPL, terminal emulator, or replacement shell.
- **Stays quiet when you type real commands.** A local, deterministic classifier decides before any network call, so `git status` costs no latency and no quota.
- **Refuses to guess.** Input that is genuinely ambiguous is left untouched and never sent to a provider.
- **Uses the subscription you already pay for.** Codex, Claude Code, and Cursor CLI run under your existing login. Metered OpenRouter API billing is opt-in only, and there is no silent fallback to it.
- **Sends very little.** Your request, shell, OS, architecture, a privacy-normalised directory label, and a fixed list of detected tools. Never shell history, environment variables, file contents, or your username.

## Requirements

| | |
|---|---|
| **OS** | macOS or Linux, on `arm64` or `amd64` |
| **Shell** | Zsh (full Smart Enter), or Bash 4.3+ (explicit translation) |
| **Provider** | One of: Codex CLI, Claude Code, Cursor CLI, or an OpenRouter API key |

Bash integration needs 4.3 or newer so humansh can safely capture and restore existing Readline bindings. macOS still ships Bash 3.2 — install a current one with `brew install bash`. Setup reports each installed shell and continues with Zsh if Bash is too old.

## Install

```sh
curl -fsSL https://humansh.com/install | bash
```

This downloads the installer, fetches the matching binary from the latest release, and verifies its SHA-256 checksum before installing to `~/.local/bin`. No `sudo`, and no third-party software is installed on your behalf.

From a checkout:

```sh
./scripts/install.sh --local
```

Then follow the guided setup. It detects every supported shell on the machine, so you do not need to know or select your current one:

```sh
humansh setup
```

Setup shows you the shell modes, provider, model, privacy setting, timeout, and shortcuts, plus the exact startup-file patches it will apply — and writes nothing until you confirm. `--yes` runs it non-interactively. See [docs/setup.md](docs/setup.md) for the full flow, including OpenRouter key handling and pinning a specific provider executable.

Open a new terminal, then try:

```text
show me the largest files in this folder
```

After an interactive installation completes, Humansh shows a short walkthrough using the configured shell controls. The Zsh guide teaches the two-Enter translate/review/execute flow when Smart Enter is enabled. If Bash is configured, the user can opt into its separate guide, which teaches the force-translation shortcut because Bash keeps Enter for normal commands. Run `humansh onboarding`, `humansh onboarding zsh`, or `humansh onboarding bash` to repeat the walkthrough later.

## Keys and shell modes

| Key | Zsh | Bash 4.3+ |
|---|---|---|
| `Enter` | Classify as literal, natural language, or ambiguous | Normal Readline `accept-line`; runs reviewed low/medium-risk output |
| `Ctrl-G` | Force translation | Translate the current line for review |
| `Ctrl-X` `Enter` | Force literal execution; confirm high-risk output | Same |
| `Escape` | Clear the line and cancel pending output | Same |

Zsh gets Smart Enter — one key that decides. Bash uses explicit translation because Readline cannot safely make Enter conditionally replace the buffer.

`Ctrl-G` replaces the stock abort/list-expand binding, and `Escape` replaces its prior action in the supported keymaps (in vi insert mode it clears the line rather than entering command mode). Setup reports every collision, and all four are configurable. Run `humansh-bindings` in either shell to see active and captured bindings.

While a provider works, both integrations show `Translating with <provider>…`. `Escape` cancels the provider process tree immediately; `Ctrl-C` cancels and restores your original text.

## How classification works

humansh classifies **intent**, not syntax — `find all files modified today` parses as a valid command but probably isn't one. Every line gets one of three outcomes:

| Outcome | What happens |
|---|---|
| `literal` | Runs normally. No provider call. |
| `natural_language` | Translated, validated, risk-scored, inserted for review. |
| `ambiguous` | **Left untouched.** No provider call. Use `Ctrl-G` or `Ctrl-X Enter` to decide. |

Scoring is local, deterministic, and inspectable — never an LLM:

```sh
print -rn -- 'find all files modified today' \
  | humansh classify --shell zsh --first-token-kind command
```

Teach it your project's commands and your own phrasing:

```sh
print -rn -- 'deploy'          | humansh classifier add-command
print -rn -- 'explain how to'  | humansh classifier add-english-prefix
```

Full rules, weights, and the grammar lexicon: [docs/classification.md](docs/classification.md).

## Providers

| Provider | Billing | Requirement |
|---|---|---|
| `codex` | ChatGPT subscription | "Sign in with ChatGPT". API-key auth rejected. |
| `claude` | claude.ai subscription | claude.ai login. Console/API/cloud overrides rejected. |
| `cursor` | Cursor subscription | Cursor browser login. API-key and custom endpoints rejected. |
| `openrouter` | **Metered API key** | A model proven against humansh's strict-output schema. |

```sh
humansh provider list          # readiness at a glance; --json for scripts
humansh provider use codex
humansh provider test codex
humansh provider configure openrouter --model provider/model
```

Every translation runs the provider in an empty temporary directory with a minimal environment, tools disabled, and no session persistence. A rejected isolation setting fails closed rather than downgrading. CLI providers are selectable only once a version floor and direct capability probes confirm each mandatory control.

**There is no silent fallback to metered OpenRouter.** See [docs/providers.md](docs/providers.md).

## Configuration

```sh
humansh config list                        # every supported key
humansh config get working_context
humansh config set shell.force_translate_binding '^X^T'
humansh config set shell.smart_enter false
```

Configuration lives under `${XDG_CONFIG_HOME:-$HOME/.config}/humansh/`. Secrets are kept in your OS keychain, never in `config.toml`, and are never printed by `config list`, `config get`, or `doctor --json`. Open a new terminal after changing a binding.

## Diagnostics and uninstall

```sh
humansh doctor          # read-only health check
humansh doctor --fix    # repair local, deterministic problems only
humansh uninstall       # keeps config and credentials
```

`humansh uninstall --purge` removes configuration and credentials too, after an explicit confirmation. Common failures and their exact fixes: [docs/troubleshooting.md](docs/troubleshooting.md).

## Contributing

Contributions are welcome. `main` is protected: all changes arrive by pull request and require review.

```sh
make verify   # format, lint, architecture, classifier, unit, race, and PTY tests
```

Please run it before opening a PR — CI runs the same gate on Ubuntu and macOS. Behaviour changes to the classifier need corpus fixtures; changes to provider isolation need the matching contract tests. See [docs/architecture.md](docs/architecture.md) for module boundaries, which the build enforces.

## Security

Report vulnerabilities through this repository's private security-advisory mechanism, not a public issue. See [SECURITY.md](SECURITY.md) and [docs/security.md](docs/security.md) for the threat model and the guarantees humansh does and does not make.
